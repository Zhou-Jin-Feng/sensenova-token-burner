# SenseNova Token Burner

面向 Windows 的 SenseNova Token Plan 用量与运行管理面板，提供自带运行时的Windows预览安装包。

**[下载 v0.1.0-preview.1 Windows MVP 预览版](https://github.com/Zhou-Jin-Feng/sensenova-token-burner/releases/tag/v0.1.0-preview.1)**（Windows 11 x64，安装包约35.60MiB）。下载Setup.exe后安装，填写自己的API key即可校验连接并手动开始；详见 [首次使用](docs/首次使用.md)。

目标是从 GitHub Release 下载并安装，打开面板填写自己的 API key 后点击开始；官方地址预填固定，运行时自带，用户无需 Codex 或开发环境。已接通 key输入、连接校验、手动运行、周期计划、托盘和重开核查。首个预览Setup约35.60MiB，安装文件约117.62MiB；隔离安装/卸载与默认目录窗口启动通过。真实key模型查询及一次短请求通过，确认119 tokens，停止后usage落盘、0在途/未知；完整窗口输入、长请求校准与返赠到账仍未验证，见 [Windows安装包](docs/Windows安装包.md)。历史导出和大规模美化延后，优先基本安装使用。

当前正式技术与平台：C# + WinForms、.NET 10 LTS、Windows 11 x64；安装包采用自包含发布，携带所需运行时。已根据资源对照从WPF迁移，核心、API和配置模块复用；正式程序资源及隔离静默安装已测，完整安装窗口使用尚未确认。

2026-10-06真实最小调用：固定官方地址返回9个模型；`sensenova-6.8-flash-lite`上下文262144、最大输出65536。使用安装包Core/Infrastructure完成短输入、最大输出32的单请求，官方usage为87输入+32输出=119 tokens。持久引擎暂停/停止收尾及最终落盘一致，周期计划未启用。此结果不代表34万字符请求、1.2亿目标或官方专属积分扣减/返赠已经验证；已知边界见 [安装包报告](docs/Windows安装包.md)。

目标流程：安装客户端，输入自己的 API key，选择参与官方返赠活动的 Flash-Lite 模型，通过“预计专属积分消耗比例”选择本轮目标后启动任务。默认 95% 档对应 1.2 亿 tokens，50% 档对应 6000 万 tokens；比例是校准后的预计值。

比例控件已确认采用 0%～95% 滑条，配 25%、50%、75%、95% 预设，分别对应 3000 万、6000 万、9000 万、1.2 亿 tokens；其他比例按校准表分段插值，0% 不发请求。首版服务地址固定为 `https://token.sensenova.cn/v1`。

计划运行支持设置“每隔 N 小时运行一次”，默认间隔 5 小时。面板已接计划开关、下次本地时间和重开提示：启用立即首轮，之后按启用时间锚定，无重叠、错过不补跑，关闭计划与停止本轮分开。轮间修改比例或间隔后保存，用于下一轮；重开保持关闭，确认记录并校验后手动启用。详见 [面板周期计划](docs/面板周期计划.md)。

已实现的使用规则：API key 按当前 Windows 用户加密保存；首次手动启用计划，重开时询问恢复；关闭或最小化窗口隐藏到托盘继续运行。托盘提供显示面板、停止本轮、关闭未来计划和退出；面板或托盘“退出”才关闭计划并收尾。常规自动回归使用虚拟key，另有获准真实短调用；桌面入口限制同一 Windows 用户只能运行一份应用。详见 [托盘与退出](docs/托盘与退出.md)。

轻量化验收目标：待机平均 CPU ≤1%、全部应用进程总工作集 ≤100 MiB，运行时总工作集 ≤150 MiB。最新完整计划mock首轮34万字符/最多3并发/1.2亿虚拟目标：运行峰108.43MiB，普通窗口等待20秒峰102.41MiB（略超目标），托盘等待20秒峰96.19MiB、CPU约0.004%；等待零请求/零状态写入，正常退出0。按首版交付优先记录小幅超标，不继续重复优化测试。真实API资源、长期等待与安装资源仍待验证；历史通过与失败样本保留在 [资源报告](docs/资源基线测量.md)。

根据 2026-10-05 核查的官方规则，实际消耗 Flash-Lite **专属积分**可获得通用积分返赠；使用通用积分的消耗不参与返赠。专属积分不足后，平台会继续扣除通用积分。返赠按每小时结算到账，每笔积分自到账起 30 天有效。

拟议默认策略：每轮目标 1.2 亿 tokens。维护者报告已多次实测，在当前 Flash-Lite 请求方式、每轮开始约 60,000 点专属积分的条件下，可消耗约 58,000 点并保留约 2,000 点，未消耗通用积分。本项目尚未独立复现；该经验值不是平台计费公式，更换模型或请求结构后需要重新校准。

准确余额、扣减来源与到账结果以 SenseNova 官方账户记录为准。余额接口与积分换算仍待确认，首版采用可配置的 token 目标和在途请求控制，积分查询作为后续增强项。

## 开发环境

开发使用 .NET SDK `10.0.401`，由根目录 `global.json` 固定版本。普通用户使用后续自包含安装包，无需安装 SDK。

开发者可从 [微软发布元数据](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json) 获取对应 Windows x64 ZIP，按其中的 SHA-512 校验后解压到 `.local/dotnet`，或使用本机同版本 SDK。项目内工具与缓存不进入 Git。

最新验证（2026-10-06）：Release 0 警告/0 错误、299/299 测试通过（0 跳过）；计划基线292项，新增7项托盘窗体行为测试。独立虚拟HTTP另验证四组托盘场景/36内部检查：隐藏运行、菜单启停分离、恢复同步、重复隐藏零新增、十秒计划等待记录不变及内外部退出0。此前两组计划控件、六组手动运行控件与300.007秒暂停最小化证据保留，部分人工保存/开始暂停已核对；原进程消失原因仍未知。资源方法与最新结果见 [资源报告](docs/资源基线测量.md)。阶段1、2已获用户确认；完整外部输入和视觉、真实长请求、实际系统休眠/关机、长期等待和无SDK新系统安装仍未验证。见 [托盘报告](docs/托盘与退出.md)、[面板计划](docs/面板周期计划.md)、[退出诊断](docs/最小化与退出诊断.md)。

在项目根目录使用 PowerShell 开发命令；脚本临时配置 SDK 和缓存目录，并关闭 CLI 遥测与自动开发证书生成：

```powershell
& .\scripts\dev.ps1 restore
& .\scripts\dev.ps1 build
& .\scripts\dev.ps1 test
& .\scripts\dev.ps1 run
```

开发命令进入模拟模式：点击“校验连接并读取模型”，选择活动模型和比例，再点击“开始本轮”运行完整虚拟目标，或显式启用默认5小时周期计划；也保留一次短模拟探针。保存配置不发请求、不启用计划。关闭或最小化隐藏到托盘，需从面板或托盘“退出”正常结束。模拟模式没有真实扣费或返赠。

开发脚本把模拟资料写入 `.local/mock-profile/`：`mock-settings.json` 不含 key，`mock-credential.dat` 为当前 Windows 用户 DPAPI 密文。普通启动编译程序使用真实 HTTP，资料写入 `%LOCALAPPDATA%/SenseNova.TokenBurner/User/`：`settings.json` 无 key，`api-key.dat` 为 DPAPI 密文，`run-state.json` 只含安全运行统计。`--mock` 或 `SENSENOVA_MOCK_PROFILE` 显式启用模拟模式，未指定测试目录时使用 `Demo/`。内置 mock 是进程内 HTTP 终端处理器，不访问网络、不监听端口、不启动额外服务；真实模式只在用户点击校验时 GET 模型，点击开始时 POST 消耗；启动、保存和恢复确认均无自动请求。

新增或升级依赖时有意执行 `& .\scripts\dev.ps1 restore -UpdateLockFiles`，复查锁文件后再执行普通 locked restore。更多接口与验证边界见 [基础架构与开发](docs/基础架构与开发.md)。

构建后可运行 `& .\scripts\verify-resource-sampling.ps1` 检查 CPU 计算精度，再运行 `& .\scripts\measure-resources.ps1` 测量正式 WinForms 窗口。采样脚本使用独立虚拟配置，每秒采样应用进程，默认预热 10 秒、待机 120 秒、模拟调用 60 秒，结束后应用自行退出；Schema 2 报告保存到忽略的 `.local/verification/resources/`。普通启动不会执行测量负载。

完整引擎测量用 `& .\scripts\measure-resources.ps1 -Baseline Engine -WarmupSeconds 10 -IdleSeconds 120 -LoadSeconds 120`：裸引擎和带 20 条历史的持久入口分别运行完整虚拟目标，再对真实五小时配置的等待状态采样 120 秒；120 秒负载参数是每轮完成时限。它使用进程内 HTTP mock，记录分配、逻辑 IO 和保存耗时，没有真实请求或积分消耗。详细方法、优化前失败与复测数据见资源报告。

构建后可运行 `& .\scripts\verify-recovery-process.ps1` 验证底层跨进程恢复；隔离 helper 不打开窗口、不使用真实 key，报告与测试资料保存在 `.local/verification/`。运行入口的记录由 `run-state.json` 保存，历史最多 20 条、文件上限 64 KiB；真实和模拟面板均已使用该入口。详见 [运行记录与人工恢复](docs/运行记录与人工恢复.md)。

新增完整面板测量：`& .\scripts\measure-resources.ps1 -Baseline Panel -WarmupSeconds 10 -IdleSeconds 120 -LoadSeconds 120`，走输入生成、MainWindowViewModel、持久运行和界面状态更新，再等待120秒。只允许mock；不能替代实际点击或真实账户验收。

阶段3最小面板历史完整mock复测：运行峰113.62MiB、负载后等待峰91.53MiB，等待CPU读数0.000%，705笔/119855640虚拟tokens，退出0；初测待机100.70MiB未达目标也保留在报告中。计划与托盘的后续资源样本另列于报告，历史数字不当作当前全部场景保证；完整视觉和真实账户尚未验证。
