# SenseNova Token Burner

面向 Windows 的 SenseNova Token Plan 用量与运行管理面板，计划提供可直接安装的客户端。

目标是从 GitHub Release 下载并安装，打开面板填写自己的 API key 后点击开始；官方地址预填固定，运行时自带，用户无需 Codex 或开发环境。目前 WinForms 模拟面板、加密配置、单轮控制、完整请求/保守预算、异常保护、周期调度和跨重启人工恢复已通过自动验证，真实 key、运行引擎、调度和恢复尚未接入面板，尚无安装包。详见 [安装版交付进度](docs/安装版交付进度.md)。

当前正式技术与平台：C# + WinForms、.NET 10 LTS、Windows 11 x64；安装包采用自包含发布，携带所需运行时。已根据资源对照结果从 WPF 迁移，核心、API 和配置模块复用；已完成正式程序资源复测，安装验收尚未进行。

目标流程：安装客户端，输入自己的 API key，选择参与官方返赠活动的 Flash-Lite 模型，通过“预计专属积分消耗比例”选择本轮目标后启动任务。默认 95% 档对应 1.2 亿 tokens，50% 档对应 6000 万 tokens；比例是校准后的预计值。

比例控件已确认采用 0%～95% 滑条，配 25%、50%、75%、95% 预设，分别对应 3000 万、6000 万、9000 万、1.2 亿 tokens；其他比例按校准表分段插值，0% 不发请求。首版服务地址固定为 `https://token.sensenova.cn/v1`。

计划运行支持设置“每隔 N 小时运行一次”，默认间隔 5 小时。底层调度已模拟验证：启用立即首轮，之后按启用时间锚定，无重叠、错过不补跑，关闭计划与停止本轮分开。计划开关和下次运行时间尚未接入面板。

已确定的正式版使用规则：API key 按当前 Windows 用户加密保存；首次手动启用计划，重开时询问恢复；关闭窗口进入托盘继续运行，托盘提供停止和退出。当前用虚拟 key 验证加密保存；调度与人工恢复已底层验证，面板开关/恢复提示和托盘尚未实现，模拟面板关闭即退出。桌面入口已限制同一 Windows 用户只能运行一份应用。

轻量化验收目标：待机平均 CPU ≤1%、全部应用进程总工作集 ≤100 MiB，运行时总工作集 ≤150 MiB。完整请求 mock 复测使用 34 万字符、最多 3 并发、两轮各 1.2 亿虚拟 token 目标：裸轮/持久轮工作集采样峰值 90.80/94.66 MiB，负载后五小时计划等待采样 120 秒，峰值 91.00 MiB、CPU 平均读数 0.00%，目标达标。等待期间零请求、零状态写入；单进程正常退出。真实 API、长期托盘和安装包仍待验证，历史短请求/WPF 对照保留在 [资源基线报告](docs/资源基线测量.md)。

根据 2026-10-05 核查的官方规则，实际消耗 Flash-Lite **专属积分**可获得通用积分返赠；使用通用积分的消耗不参与返赠。专属积分不足后，平台会继续扣除通用积分。返赠按每小时结算到账，每笔积分自到账起 30 天有效。

拟议默认策略：每轮目标 1.2 亿 tokens。维护者报告已多次实测，在当前 Flash-Lite 请求方式、每轮开始约 60,000 点专属积分的条件下，可消耗约 58,000 点并保留约 2,000 点，未消耗通用积分。本项目尚未独立复现；该经验值不是平台计费公式，更换模型或请求结构后需要重新校准。

准确余额、扣减来源与到账结果以 SenseNova 官方账户记录为准。余额接口与积分换算仍待确认，首版采用可配置的 token 目标和在途请求控制，积分查询作为后续增强项。

## 开发环境

开发使用 .NET SDK `10.0.401`，由根目录 `global.json` 固定版本。普通用户使用后续自包含安装包，无需安装 SDK。

开发者可从 [微软发布元数据](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json) 获取对应 Windows x64 ZIP，按其中的 SHA-512 校验后解压到 `.local/dotnet`，或使用本机同版本 SDK。项目内工具与缓存不进入 Git。

最新验证（2026-10-06）：Release 0 警告/0 错误、257/257 测试通过（0 跳过），包含完整测量驱动、短暂文件占用保护和并发 UTF-8 请求回归。完整 mock 负载、调度等待与落盘资源达标；正式窗口模型/用量、比例、0%/未确认模型禁用、配置/加密测试凭据保存重开、滚动及正常退出已实际操作验证。隔离 helper 退出再重开保留未知在途且零自动请求；正式 POST 送达不明时不自动重试。阶段1、2技术验收已补齐并获用户确认；真实 API、实际系统休眠、托盘、安装包尚未验证。

在项目根目录使用 PowerShell 开发命令；脚本临时配置 SDK 和缓存目录，并关闭 CLI 遥测与自动开发证书生成：

```powershell
& .\scripts\dev.ps1 restore
& .\scripts\dev.ps1 build
& .\scripts\dev.ps1 test
& .\scripts\dev.ps1 run
```

启动后点击“读取模拟模型”，选择活动模型，再点击“模拟调用一次”。“保存模拟配置”只保存比例、间隔、模型及凭据保存选项；默认间隔 5 小时，当前不会执行定时任务。单次模拟调用不会执行面板显示的完整 token 目标，也没有真实扣费或返赠。

开发脚本把模拟资料写入 `.local/mock-profile/`：`mock-settings.json` 不含 key，`mock-credential.dat` 为当前 Windows 用户 DPAPI 密文。直接启动编译后的程序时，默认目录为 `%LOCALAPPDATA%/SenseNova.TokenBurner/Demo/`。内置 mock 是进程内 HTTP 终端处理器，不访问网络、不监听端口、不启动额外服务；当前没有真实 key 输入入口。

新增或升级依赖时有意执行 `& .\scripts\dev.ps1 restore -UpdateLockFiles`，复查锁文件后再执行普通 locked restore。更多接口与验证边界见 [基础架构与开发](docs/基础架构与开发.md)。

构建后可运行 `& .\scripts\verify-resource-sampling.ps1` 检查 CPU 计算精度，再运行 `& .\scripts\measure-resources.ps1` 测量正式 WinForms 窗口。采样脚本使用独立虚拟配置，每秒采样应用进程，默认预热 10 秒、待机 120 秒、模拟调用 60 秒，结束后应用自行退出；Schema 2 报告保存到忽略的 `.local/verification/resources/`。普通启动不会执行测量负载。

完整引擎测量用 `& .\scripts\measure-resources.ps1 -Baseline Engine -WarmupSeconds 10 -IdleSeconds 120 -LoadSeconds 120`：裸引擎和带 20 条历史的持久入口分别运行完整虚拟目标，再对真实五小时配置的等待状态采样 120 秒；120 秒负载参数是每轮完成时限。它使用进程内 HTTP mock，记录分配、逻辑 IO 和保存耗时，没有真实请求或积分消耗。详细方法、优化前失败与复测数据见资源报告。

构建后可运行 `& .\scripts\verify-recovery-process.ps1` 验证底层跨进程恢复；隔离 helper 不打开窗口、不使用真实 key，报告与测试资料保存在 `.local/verification/`。运行入口的记录由 `run-state.json` 保存，历史最多 20 条、文件上限 64 KiB；当前模拟面板尚未接入该入口。详见 [运行记录与人工恢复](docs/运行记录与人工恢复.md)。
