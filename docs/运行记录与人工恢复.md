# 运行记录与人工恢复

更新：2026-10-06。阶段 2 步骤 5 已通过自动测试与隔离进程验证。当前提供底层持久运行入口，恢复提示、历史展示、真实 key 和运行按钮留到阶段 3 接入；桌面入口已取得当前 Windows 用户的单实例锁。

## 用户操作与恢复规则

| 情况 | 行为 |
| --- | --- |
| 首次使用，无运行记录 | 初始化不发请求；用户可明确开始单轮或启用计划 |
| 正常结束后重开 | 等待用户确认恢复，不启动模型消耗或计划 |
| 上次未结束、存在在途或未知用量、需核查 | NeedsReview；普通继续或新开均拒绝，先核查，再明确确认 |
| 用户确认恢复 | 保存确认结果；保持计划关闭，不发请求；仍须另行开始或启用 |
| 再次启用计划 | 以本次启用时间建立新锚点，立即首轮；不续跑旧轮或补跑离线周期 |
| 记录损坏、未知版本、无法读取 | Corrupt；保留原文件，不以空状态覆盖；不能用普通确认解除 |
| 保存失败 | StorageFailed；停止新增并关闭未来计划，本次会话不能继续；已发出的请求仍收尾并保留可获得的用量 |

“确认已核查”不代表客户端查到了账户余额或已证明没有扣费。记录保留上次已确认 usage、未知数量、在途数量与 ReviewedUtc，不把未知改成零。新轮开始时旧轮进入历史，最多保留最近 20 条；历史有界，适合故障核查，不能替代完整官方账单。

## 文件和兼容

普通配置 `mock-settings.json` 使用 schema 2，兼容 schema 1；旧版本只在内存升级，比例、小时数、模型和凭据保存选项保留，下一次显式保存才写新版本。保留原文件名和目录，避免改变路径导致原配置丢失。未知未来版本拒绝读取。

运行资料保存在注入目录的 `run-state.json`，schema 1，包含当前轮、历史和计划意图。计划意图用于恢复展示，不能视为重开已启用；计划锚点与定时任务不会跨进程恢复。Core 的 `PersistentRunSession` 聚合引擎、调度与记录，面板应统一调用该入口，不能改用不带存储的裸引擎绕过保护。

记录字段只有运行参数、usage、计数、状态/安全失败分类、UTC 时间及计划参数。不保存 API key、账户密码、请求输入、模型回答、原始响应或异常正文。凭据仍单独使用 Windows 当前用户 DPAPI 密文。

所有用户文件读取上限 64 KiB；运行历史最多 20 条。保存复用同目录唯一临时文件，完整写入后替换目标，失败/取消保留此前完整记录，清理本次临时文件。运行记录严格校验必需构造字段、版本、未知字段、枚举、非负 usage、预留、并发和时间。此机制未提供断电、磁盘硬件损坏或手工删除记录后的完整性保证；普通配置与运行文件也不构成跨文件事务。

Windows短暂读锁可能阻止替换。仅运行记录对系统错误5/32/33最多异步等待10×50ms，临时文件只写一次；持续占用仍进入StorageFailed，取消保留原文件。普通配置/DPAPI不启用新等待，不修改权限、不重发模型请求。错误只附安全系统编号，不保存原始异常或路径；完整负载失败的外部占用程序尚未确认。

## 请求前后的顺序

1. 初始化读记录并检查恢复门槛，构造不发送请求。
2. 用户明确开始后，先保存本轮起始记录。
3. 每笔请求预留预算，再等待在途快照保存成功，才执行请求。落盘等待中暂停/停止会撤销未发送预留，不发出该请求。
4. 结果结算后保存已确认 usage 和剩余在途，再决定是否新增；未知结果停止新增。
5. 最终状态保存后才完成运行任务、释放运行互斥。如果最终保存等待期间停止宽限到期，还要保存新的保护状态。

异常退出发生在请求发出后、结果记录保存前时，最后完整记录仍包含在途数量。重开把这些记录视为用量不明，先核查；它们不是仍在本机执行的任务，也不能当作零扣费。即使退出发生在保存预留后、实际发送前，也采用保守核查。

写入串行化，只有一个等待的检查点，没有落盘后台队列、逐 token 写入或定时刷日志。每轮起止及每请求发前/结算各保存一次；计划变更按操作保存。最终状态并发变化可能追加一次校准写入。步骤6完整mock测得705笔对应1413次保存、20,494,331逻辑字节（约19.54MiB），写入累计8,158.67ms、单次最大65.03ms，最大文件14,507字节；预置20历史仍有界。等待120秒零状态写入；逻辑IO不等于物理磁盘写放大，详见 [资源报告](资源基线测量.md)。

## 单实例

Desktop 在创建窗口前取得 `%LOCALAPPDATA%/SenseNova.TokenBurner/application.lock` 的独占文件句柄；切换开发 profile 仍复用同一用户锁。第二实例提示已有程序并退出，无法取得锁的权限错误安全报错。持有期间不删除锁文件；正常退出或进程直接退出后操作系统释放句柄，遗留文件不阻止下次启动。

只保证当前 Windows 用户和此入口的一份应用实例。不同 Windows 用户、其他客户端或其他 key 仍可能消耗同一个 SenseNova 账户积分池。
