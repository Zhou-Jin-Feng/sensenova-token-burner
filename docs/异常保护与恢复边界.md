# 异常保护与恢复边界

更新：2026-10-06。阶段 2 步骤 3 已实现，并以虚拟凭据、终端 HTTP mock 和可控时间验证。当前桌面仍为模拟面板，这些状态与操作尚未接入正式按钮；没有使用真实 key 或消耗积分。

## 运行遇到错误时的动作

| 情况 | 本轮行为 | 用量与恢复 |
| --- | --- | --- |
| 认证、参数或模型错误 | 停止新增，汇总其他在途结果，结束为 Faulted | 明确本地未发出或 HTTP 拒绝的请求分开计数；先修正配置，再显式开始 |
| HTTP 429 | 进入 AwaitingReview，收集其他在途结果，不自动重试 | 官方错误码同时表示限流或额度受限；保留未知用量，普通 Resume 无效 |
| 5xx、断网、HTTP 408、响应读取中断 | 停止新增并收尾 | 无法确认服务端执行情况，保留未知请求数；不盲重试 |
| 缺失、坏 JSON、非法或不能汇总的 usage | 停止新增并收尾，保留此前确认用量 | 不把未知请求记为零；需要核查 |
| 可信适配器确认尚未发出的暂时故障 | 收齐其他在途后有限异步退避 | 仅 Network/Transient 且 Delivery=NotSent 可自动重试；未知送达或 Rejected 不满足条件 |
| 请求超时 | 默认 2 分钟请求取消并停止新增 | 时限覆盖等待响应正文；更短的 HttpClient 时限仍可提前结束；晚到有效 usage 仍累计 |
| 停止收尾超时 | StopAsync 默认等待 15 秒后返回 Stopping/StopWaitExpired，并异步请求取消 | 未结束的请求仍保留在途数与预留，RunAsync 的任务未完成且互斥不释放；不会宣称强制停止成功 |
| 运行记录写入失败 | 停止新增，关闭未来计划，收齐已经发出的结果 | 本次会话锁住，不允许普通确认后重开；重启读取最后完整记录，未知在途仍须核查 |

RequestDelivery 由可信执行阶段或 HTTP 状态赋值，不能采信错误正文自称“未执行”“未扣费”。当前适配器把 400/401/403/404/405/413/422 作为请求拒绝；429、5xx、网络或协议错误默认 Unknown。拒绝计数也不能替代官方账单核对。

## 退避上限

`RunProtectionOptions` 默认每轮最多 3 次退避，指数等待 1、2、4 秒，单次最多 8 秒、累计安排等待最多 30 秒；成功请求不会重置重试次数。同批多个未发送故障合并为一次退避，先收齐其他在途，再重新按预算决定请求数。

停止或生命周期取消立即唤醒退避；退避中暂停后，即使等待时间结束也不会补发，须普通 Resume。达到目标或预算不足无需额外重试。服务端等待提示在本地上限内才采用，超过上限就结束，不把要求的等待缩短后提前重试。

HTTP 429 的 Retry-After 只保存有效且不超过 5 分钟的数值或日期提示。它不能证明是纯速率限制或未执行，因而不会自动打开重试。当前正式 POST 适配器没有已核实的 NotSent 暂时故障路径，HTTP 消耗请求不自动重试；退避机制的可重试路径由可信请求替身验证，后续只能在获得可靠未发送依据后启用。

## 人工核查与新轮

遇到限流/额度不明、未知 usage 或收尾超时，会设置 ReviewRequired。AwaitingReview 中普通 Resume 和 AcknowledgeReview 都无效；先停止并等待原轮实际收尾，再核查账户。

原轮完成后可显式调用 AcknowledgeReview，仅确认“已核查”，不清除未知计数或修改已有完成任务中的历史快照，不发请求。之后还须另行 RunAsync 才会新开；未确认时 RunAsync 拒绝重开。该确认不等于已经取得官方余额或认定零扣费。

步骤 5 已实现请求前、结果结算及最终状态的落盘与重开人工恢复，保留未知在途/用量与核查时间；确认恢复不发请求。正式面板应使用 PersistentRunSession 统一控制。调度遇保护信号立即关闭未来计划，核查后仍需显式重新启用，不自动确认、不新建裸引擎绕过门槛。此前已发出的请求可能消耗积分，这套保护仍不能保证精确积分上限。见 [运行恢复](运行记录与人工恢复.md)、[周期调度](周期调度与时间规则.md)。
