# 周期调度与时间规则

更新：2026-10-06。阶段 2 步骤 4 已实现并通过 mock 和可控时间验证；阶段3已接入真实/模拟手动运行与key，计划开关、托盘与下次运行时间展示仍待后续接入。

## 用户操作对应的行为

| 操作 | 行为 |
| --- | --- |
| 打开程序或保存配置 | 构造/更新调度配置均不启动计划或请求；当前没有计划自动恢复 |
| 显式启用计划 | 立即开始首轮，以启用时间为 UTC 锚点，默认下轮在 5 小时后；可用其他有效小时数 |
| 改比例或模型 | 当前轮仍使用原参数；下一轮取新的不可变配置 |
| 改小时间隔 | 按原启用锚点计算新的未来周期，不立即补跑；已经处理的周期不会因修改或时钟回拨重复执行 |
| 停止本轮 | 停止新增并收尾当前请求，计划保持启用，下一周期仍可运行；若收尾出现未知用量/超时则按保护规则关闭计划 |
| 关闭计划 | 停止未来定时任务，清空下次运行时间；当前轮继续收尾，不隐式取消请求 |
| 重新启用 | 必须显式调用，重设锚点并立即开始首轮；旧计划/原轮未收尾或尚需核查时拒绝 |
| 0% | 首次启用返回 false，零请求/零定时；运行中改 0% 关闭未来计划，当前轮仍保留原目标，停止本轮需单独操作 |
| 退出调度 | 关闭未来计划、停止本轮；非合作请求可能返回 Stopping，仍保留在途和引擎互斥，不声称已经强制结束 |

例：08:00 手动启用、默认 5 小时，周期锚点为 08:00、13:00、18:00。首轮 08:20 结束不会把下轮推到 13:20。若 13:00 前一轮仍在运行或暂停，就跳过这一周期，结束后不立即补跑，等待 18:00。

本模块管理单进程中的同一引擎；步骤 5 已提供单实例入口及统一持久运行控制 PersistentRunSession，重开确认后仍须另行启用计划，详见 [运行恢复](运行记录与人工恢复.md)。不得把客户端间隔或下次运行时间显示成 SenseNova 官方额度恢复倒计时。

## 时间变化与错过周期

时间以 UTC 保存，显示时才按本地时区转换；换时区不会更改周期。调度同时读取 TimeProvider 的 UTC 和单调时间，正常定时唤醒允许最多 30 秒迟到；超过容差或错过多个周期就跳过过去周期，直接等待下一个未来边界。

每次唤醒比较 UTC 增量与单调增量；明显偏差超过 5 秒或单调时间倒退视为时钟变化，重排未来周期并阻止该次补跑。系统时间前移跳过已错过的边界；回拨保留已处理时间的水位，不能再次运行已处理周期。时间前移/回拨不改变当前轮的参数或请求。

例如默认五小时计划在启用 16 小时后才再次得到执行机会，跳过第 5、10、15 小时三次机会，等待第 20 小时。大跨度的错过计数用算术计算，不逐个循环补跑。若未来日期无法表示，安全关闭计划，不新增消耗请求。

休眠只通过受控时钟/迟到唤醒测试验证；没有实际执行 Windows 睡眠或唤醒操作，不能将模拟行为视为所有硬件电源状态的实测。

## 异常与轻量化

运行引擎的保护信号会立即唤醒调度，认证/参数/模型错误、预算低估、未知用量、429 待核查或超时均关闭未来计划；不等五小时或一分钟检查。确认核查不会自动恢复计划，必须用户显式重新启用。当前轮晚到用量仍保留，关闭计划不释放还在执行请求的互斥。详见 [异常保护](异常保护与恢复边界.md)。

等待使用 Task.Delay(TimeProvider) 和异步完成信号，没有额外服务、进程或占线程的等待循环。长等待最多每分钟检查一次时钟，以便识别系统时间变化；配置更新、关闭、当前轮完成和保护信号立即唤醒。关闭计划会等待调度任务退出，并释放它的定时器；退出仍须单独收尾请求。

小时数以 decimal 转 ticks，允许可表达且至少一秒的间隔，避免极小数输入产生零等待。该限制为内部防空转校验，首版用户仍按小时选择，无需填写 token 估计或其他实现参数。等待队列只有本轮句柄/信号/一个调度定时器，不按周期增长历史列表。
