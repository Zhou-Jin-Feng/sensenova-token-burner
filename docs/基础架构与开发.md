# 基础架构与开发

Windows 11 x64、.NET 10、WinForms 单进程桌面应用。没有后台服务、浏览器运行层或独立进程；托盘、调度和全部任务都在同一个进程里。

## 源码结构

```text
SenseNova.TokenBurner.slnx
global.json                  固定 SDK 10.0.401
Directory.Build.props        可空引用、警告即错误、锁文件还原
installer/windows.iss        Inno Setup 安装脚本
scripts/                     dev.ps1、安装包构建、资源测量与环境校验
src/
  SenseNova.TokenBurner.Core/            比例策略、配置、运行引擎、调度、持久运行入口
  SenseNova.TokenBurner.Infrastructure/  官方 HTTP 适配器、mock、原子文件、DPAPI、实例锁、任务目录
  SenseNova.TokenBurner.Desktop/         入口、多任务面板、协调器、自绘界面
    ViewModels/MultiTaskCoordinator.cs   多 key 任务、共享并发、预览与通知
    MultiTaskForm.cs                     主窗口：视图组合、操作流程、托盘
    Ui/                                  主题、DPI、自绘控件、视图、对话框
tests/SenseNova.TokenBurner.Tests/       MSTest
```

| 项目 | 职责与依赖 |
| --- | --- |
| Core | 比例校准、任务配置、单轮引擎（预算、在途预留、保护）、周期调度、`PersistentRunSession`；不依赖界面或 Windows 凭据 |
| Infrastructure | 固定官方地址、HTTP 适配器与 mock、原子文件、运行记录 JSON、用户实例锁、Windows DPAPI；依赖 Core |
| Desktop | `Program` 单实例入口、`MultiTaskForm` 面板、`MultiTaskCoordinator`；依赖 Core 与 Infrastructure。旧单 key 的 `MainForm`/`MainWindowViewModel` 只供资源探针使用 |
| Tests | 规则、存储、HTTP 协议、引擎、协调器和面板行为；不进入安装包 |

唯一的第三方运行依赖是微软 `System.Security.Cryptography.ProtectedData`（DPAPI）。依赖锁文件记录精确还原结果。

## 运行规则

- **目标**：`ConsumptionPolicy.GetTargetTokens` 接受 0–95，按 0/25/50/75/95% → 0/3000万/6000万/9000万/1.2亿 tokens 分段插值；也支持自定义目标。这只是经验策略，不是官方计费公式。
- **任务**：每个 key 一个任务，有独立的 `PersistentRunSession`、检查点和历史。同一 key 不会被两个任务同时使用（按 key 摘要互斥，摘要不落盘）。
- **并发**：全应用共享 `RequestConcurrencyLimiter`（1–10，默认 3）。每轮的单 key 上限为 `min(单 key 上限, 共享上限)`（单 key 上限 1–10，默认 3）。引擎先拿到共享许可再计入在途，等待许可不占预算。
- **请求**：每笔为约 34 万字符的程序合成输入，输出上限 1,024；本地按 240,000 输入 + 1,024 输出预留。临近目标时降为单并发，预算不足时提前结束；usage 以官方返回为准。
- **保护**：认证、参数、模型错误直接停止。429 不自动重试，进入核查。可信的“未发送”暂时故障才有限退避。请求默认 2 分钟超时，停止宽限 15 秒。未结束的请求不释放互斥。
- **持久化**：请求发出前先写检查点。异常退出后重开，未完成的轮次需要人工核查后才能继续或重置，不会自动重发。记录写入失败时阻断新增请求和未来定时。
- **定时**：按 UTC 锚点计算周期；上一轮未结束时不重叠，错过的周期不补跑。支持配置自然周额度刷新周期（默认 60 万分），超额时自动跳过定时并在刷新后自动恢复。暂停和重置会关闭定时，重开应用不自动恢复定时。

## 存储

- 用户数据：`%LOCALAPPDATA%\SenseNova.TokenBurner\User\`。
  - `tasks.json`：任务索引，不含 key。
  - `Tasks\<任务ID>\`：每个任务的 DPAPI 密文和 `run-state.json`（当前轮、最多 20 条历史、计划意图）。
  - `ui-preferences.json`：主题偏好；读写失败只回退默认值。
- 旧单 key 版本的 `settings.json`、`api-key.dat`、`run-state.json` 原地保留，作为“原有任务”继续使用，不搬移、不改写。
- 写入一律先写同目录临时文件再原子替换，读取上限 64 KiB。损坏的 JSON 或未知字段会安全报错，并保留原文件。
- `tasks.json` 读取时拒绝未知字段，所以新版本写入的配置（如 `PerKeyConcurrency`）旧版本读不了。
- DPAPI 使用 `CurrentUser` 作用域，明文字节用完即清零；它不能隔离同一 Windows 用户下的其他程序。

## HTTP 与模拟模式

`SenseNovaHttpClient` 使用固定地址 `https://token.sensenova.cn/v1`，调用 `GET models` 和 `POST chat/completions`，禁止自动重定向。usage 必须是自洽的非负整数，否则不计为成功用量。错误提示不回显响应正文或凭据。

`--mock` 参数或环境变量 `SENSENOVA_MOCK_PROFILE` 启用进程内 `MockSenseNovaHandler`：没有网络、不监听端口，只接受内置虚拟 key（前缀 `mock-only-not-a-real-key`），数据目录也独立。`dev.ps1 run` 总是使用 mock。协议依据为 [SenseNova 官方文档](https://platform.sensenova.cn/docs) 的模型列表和 Chat Completions 章节。

## 面板

- `MultiTaskForm` 由顶栏、全局状态条、key 列表、详情区（概览、目标设置、定时、运行记录）和状态行组成，每秒按协调器快照刷新。列表每次按任务数据整表重画，不保留旧行。
- 所有联网操作都先确认：单个运行、批量运行、启用定时都会先展示 `RunPreview` 并等待确认；“验证连接”只发 GET。确认时捕获 `RunStartGuard`，状态变了就不执行旧的启动。
- 待核查的任务必须先勾选核查确认，才能运行或重置。重置和删除也需要确认。目标设置有未保存修改时，运行、启用定时或切换任务前会先要求保存或放弃。
- 界面（`Ui/`）：自绘控件继承自 `Control`、`Button` 或 `CheckBox`，保留键盘操作、无障碍名称和 `PerformClick`。`Theme` 集中定义浅色和深色色板，可跟随系统；所有尺寸按 `DeviceDpi/96` 缩放，字体按像素创建。应用以 SystemAware 模式运行。
- 窗口创建视图之前先初始化主题，避免控件持有已经替换掉的字体。
- 需要确认的交互集中在 `PanelPrompts` 里，测试可替换为不弹窗的实现；`ShowInBackground` 让测试窗口在屏幕外显示、不抢焦点。

## 开发命令

先准备 global.json 指定的 SDK 10.0.401（项目内 `.local/dotnet` 优先），然后在项目根目录用 PowerShell 执行：

```powershell
& .\scripts\dev.ps1 restore
& .\scripts\dev.ps1 build
& .\scripts\dev.ps1 test
& .\scripts\dev.ps1 run
```

- 默认使用 Release 配置，可传 `-Configuration Debug`。
- restore 默认按锁文件的 locked 模式还原；有意新增或升级依赖时才用 `restore -UpdateLockFiles`，并复核锁文件。
- 脚本只在本次调用里设置 DOTNET_ROOT、CLI 和 NuGet 缓存位置，结束后恢复原环境变量；`scripts/verify-dev-environment.ps1` 可以检查这一点。
- 测试使用 Microsoft.Testing.Platform 和 MSTest SDK 4.4.1。面板测试在屏幕外运行，不抢焦点、不弹系统通知；`TrayWindowTests` 仍会短暂打开旧单 key 窗口。

安装包构建见 [Windows 安装包](Windows安装包.md)。构建输出、缓存、日志和测试结果都不进入 Git。

## 资源

`--multi-resource-baseline <输出目录>` 是显式开发命令：在隔离 profile 里用 3 个虚拟 key、mock API 做一次 6 秒的代表性采样。当前结果见 README。旧单 key 的资源工具（`scripts/measure-resources.ps1` 等）保留为历史对照。
