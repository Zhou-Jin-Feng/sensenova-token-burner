## 2. 已确认的执行规则

- 使用当前校准映射：0/25/50/75/95% 对应 0/3,000 万/6,000 万/9,000 万/1.2 亿 tokens，其他比例分段插值。0% 不发请求；比例是经验策略，不是精确积分限额。
- 首次手动启动，保存配置不启动；重开应用后明确恢复前不发起模型消耗。运行中的配置修改作用于下一轮。
- 默认每 5 小时，可配置正数小时；周期从计划开始时间锚定。运行不重叠，错过周期不补跑，计划时间不能表示官方积分恢复时间。
- “停止本轮”与“关闭计划”分开；暂停不新增请求，已发出的请求仍须处理最终结果。暂停、继续、停止不得生成第二个并行运行实例。
- 只有一个配置 key，应用实例及引擎运行互斥。尚无官方账户标识，不能声称能阻止其他客户端或其他 key 消耗同一个账户的积分池。
- 有效 usage 才纳入已确认用量；取消、断网或缺失 usage 不能按零消耗处理。是否已被服务端执行不明确时暂停新增请求并保留未知状态，不盲目重试。
- 本阶段先验证 mock。正式模型调用、完整 1.2 亿目标和积分到账核对需分别明确真实验证范围。

## 4. 预算与异常处理边界

预算控制分开记录已确认 usage、在途请求预留和未知用量。发出新请求前检查本轮剩余目标和在途预留；达到目标或结果不明确时不再新增，并汇总可取得的在途结果。

已选并发最多 3、临近目标降 1，余量不足一笔预留即提前结束并说明原因。输入 token 估计显式提供，不能用字符数代替；估计和预留不是硬上限。大输入复用已 mock 验证，资源峰值及正式超时仍待测，原短请求 87.45 MiB 不能替代完整负载。

只有可信确认尚未发送的暂时故障才自动退避；默认每轮最多 3 次、单次 8 秒、累计安排等待 30 秒。当前 429 同时含速率和额度限制，Retry-After 也不消除歧义，因此进入 AwaitingReview；HTTP POST 送达不明不自动重试。未知用量须原轮收尾后显式确认核查才能开新轮，跨重启记录待步骤 5。

正常停止先停止新增，默认等待 15 秒后返回收尾超时并异步取消；请求默认 2 分钟时限。仍在执行的请求继续保留预留与互斥，晚到有效 usage 累计，取消无结果则保留未知。状态文件与写入失败保护待步骤 5，重开不自动消耗；不能标为“已完成且无额外消耗”。

## 5. 轻量化与验证安排

- 等待、退避和调度均使用异步定时，不忙循环；请求队列、历史记录和日志体积设上限，界面状态更新不逐 token 刷新。
- 大文本不在界面线程生成；减少并发序列化重复分配，性能调整以实际数据为准，不强制 GC 或裁剪工作集来制造达标结果。
- 长周期用可控时钟验证，无需等待真实 5 小时；补充时钟前移/回拨、休眠恢复与当前轮未完成的场景。
- 当前资源目标保持待机平均 CPU ≤1%、总工作集 ≤100 MiB，运行总工作集 ≤150 MiB；同一台机器、Schema 2 口径，记录样本、输入规模和并发。
- 真实 API、官方余额/到账、托盘和安装包分别留有验证边界。完整面板与美化属于阶段 3；托盘等待和最终安装包资源届时补测。
