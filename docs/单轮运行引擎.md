## 生命周期

`src/SenseNova.TokenBurner.Core/SingleRunEngine.cs:4` 的调用规则：

| 操作 | 行为 |
| --- | --- |
| 构造 | Idle，不发请求、不启动任务 |
| `RunAsync(parameters, cancellationToken)` | 显式开始并返回完成任务；原轮未结束时抛 `InvalidOperationException`，不覆盖原轮；0 目标直接完成且零请求 |
| `Pause()` | Running 转 Paused，停止预留新请求，在途请求继续收尾；无法转换时返回 false |
| `Resume()` | 普通 Paused 转 Running；保护暂停 AwaitingReview 和需核查状态不可继续 |
| `StopAsync(waitCancellation)` | 转 Stopping，停止新增；默认等待 15 秒，超时返回 Stopping 并请求取消，实际收尾后才结束；取消等待只影响调用者，原轮仍保持互斥 |
| `AcknowledgeReview()` | 原轮已实际结束后显式确认核查；保留历史未知计数，不自动请求；未确认不得开始新轮 |
| 生命周期取消 | 传给执行器；有效最终 usage 仍计入，在途无结果时标未知，最后 Stopped，不能宣称零额外消耗 |
| 达到目标或预算余量不足 | Completed，不新增，保留实际 usage，EndReason 区分 TargetReached 与 BudgetRemainder；估计不是硬上限 |
| 执行器异常 | 按安全分类停止/等待核查；仅可信未发出的暂时错误有限退避，未知送达不重试，不保留原始正文 |

最多三笔在途。Pause/Stop 与预留共用锁，已经预留的请求算在途；操作返回后仍可能收到最终用量。任何异常、缺失结果或预算低估停止新增，继续汇总其余在途，全部收尾后才释放互斥。最终快照与完成信号同锁更新，旧轮不会覆盖新轮。

`Snapshot` 是线程安全不可变快照，含状态、参数、已确认 usage、有效 usage 请求数、在途数/ReservedTokens、未知用量请求数、安全失败分类及结束原因；读取不启动任务。

只有非负且输入加输出等于总数的 usage 才累计，checked 加法防溢出。缺失、非法、无法汇总会结束本轮并标未知，先前确认用量不变。有效零 usage 计为已完成请求，但以 NoProgress 结束，避免无进展循环，它不计为未知。参数非法和重叠启动在入口抛安全异常；执行器异常以最终快照返回。

发生未知用量后设置 ReviewRequired 并拒绝新轮；原轮实际结束且人工确认核查后才能显式启动，历史未知计数仍保留。后续面板统一调用 PersistentRunSession，不自动确认或新建裸引擎绕过；请求前落盘和跨重启人工恢复已验证，见 [运行记录](运行记录与人工恢复.md)。

## 停止与资源边界

StopAsync 的等待或取消不代表服务端停止。引擎默认每请求 2 分钟、停止宽限 15 秒；更短的 HttpClient 超时仍生效。超过宽限返回 Stopping 并异步取消，执行器不响应时仍保留预留和互斥，迟到有效 usage 会汇总。详见 [异常保护与恢复边界](异常保护与恢复边界.md)。

没有新增依赖、进程或界面刷新；同进程异步任务执行，暂停用完成信号等待而非忙轮询。完整 34 万字符、最多 3 并发 mock 资源已测：裸轮/持久轮工作集采样峰值 90.80/94.66 MiB，CPU 平均 0.795%/2.030%（整机口径）。旧短探针数据仅保留历史对照，详见 [资源报告](资源基线测量.md)。
