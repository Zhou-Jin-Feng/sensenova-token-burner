# Windows 安装版需求与实现方案

调研日期：2026-10-05（Asia/Singapore）。本文为开发前的方案草案，未代表实现完成或发布批准。

## 1. 目标和已确认需求

将现有本地 Python 用量脚本的运行能力整理为普通用户可安装的 Windows 客户端，并在后续获准发布时通过 GitHub Release 分发安装包。

已确认：首版面向 Windows。用户安装后在面板输入自己的 SenseNova API key，选择商汤模型，启动、暂停或停止任务，查看用量与运行状态。最终业务目标是参与 Flash-Lite 消费返赠活动，获得可用于其他已授权模型的通用积分。

用户补充实测：已多次以每轮 1.2 亿 tokens 运行，在现有 Flash-Lite 请求方式下，将 60,000 点专属积分消耗到约剩 2,000 点，未消耗通用积分。首版以此作为默认策略依据，保留可调上限；本轮没有独立复现或核对官方账单。

用户已明确要求面板可选择消耗比例：95% 档映射 1.2 亿 tokens，50% 档映射 6000 万 tokens。比例控制纳入首版，而非仅放在高级设置中输入 token 数。

用户已明确要求可配置“每隔 N 小时运行一次”，默认间隔 **5 小时**，与其当前使用的积分恢复周期策略一致。该配置与消耗比例一起放在主面板。

“安装即用”的验收含义：在没有 Python、Node.js、Codex 和源码环境的 Windows 电脑上，安装并打开客户端，完成凭据配置后即可运行。运行模型仍需要联网、有效账户及相应权限。支持的 Windows 版本和处理器架构待确认。

本轮范围：查看已有 Codex 自动化及所引用脚本、核查公开规则、形成方案。尚未授权实施、真实 API 调用、修改已有任务、Git 提交或发布。

## 2. 官方规则与产品边界

来源：[SenseNova AI API 文档](https://platform.sensenova.cn/docs)，尤其是“积分”“模型列表”和“错误码”章节。以下为调研日核查结果，活动规则可能调整。

| 项目 | 核查结论 | 对客户端的影响 |
| --- | --- | --- |
| Base URL | `https://token.sensenova.cn/v1` | 默认预填，首版常规使用无需修改 |
| 当前返赠模型 | 文档介绍 Flash-Lite 消费返赠；当前可核查模型为 `sensenova-6.8-flash-lite` | 返赠模式只允许选择经过规则核查的活动模型 |
| 返赠比例 | 实际消耗 1 点 Flash-Lite 专属积分，返赠 1 点通用积分 | token 总量不能直接作为返赠积分 |
| 扣减顺序 | Flash-Lite 优先扣专属积分，不足后扣通用积分 | 需要处理专属积分耗尽后的继续扣减 |
| 不返赠的用量 | 从通用积分池扣除的消耗不参与返赠 | 不应以“请求成功”判断产生返赠 |
| 结算 | 按自然日汇总、每小时结算到账 | 运行完成与返赠到账是两个状态 |
| 有效期 | 每笔返赠积分自到账之日起 30 天有效 | 显示到期信息需有官方记录支持 |
| 滚动额度 | 两类积分池分别提供滚动 5 小时 60,000 点、滚动周 600,000 点 | 固定 5 小时定时器不能表示账户真实剩余额度 |
| 返赠额度 | 返赠积分不占用滚动 5 小时和周额度 | 不应并入周期额度计算 |
| 模型权限 | 返赠不会自动解锁模型 | 模型列表、账户权限和活动资格需要分别判断 |

返赠流程是：调用 Flash-Lite → 平台实际扣减专属积分 → 平台结算返赠 → 通用积分到账。客户端负责管理 API 任务和提供可验证的记录，不执行平台内部的积分转换。

“商汤自己的模型”与“参与返赠的模型”需要分别标注。U1.5 Lite/Fast 等商汤图片模型，不能仅因属于商汤就被标为可用于 Flash-Lite 返赠。

## 3. 现有脚本可复用的内容

两个现有 Codex heartbeat 任务分别启动两个账户的 Python 脚本，周期均为每 5 小时，目前均处于暂停状态。实际任务运行由独立后台进程承担。

可借鉴的行为：单实例锁、后台运行、HTTP 429 退避、读取历史状态、目标用量停止、认证或请求错误停止、JSON 状态与日志输出。

需要在迁移时调整：

- 两份按账户复制的脚本改为统一运行引擎，配置与凭据分离。
- 清除源码中的真实凭据、私人路径、账户标识和通知脚本，不直接复制原目录进入仓库。
- 移除对 Codex 定时任务和本机 Python 环境的依赖。
- 原默认 1.2 亿 tokens 是本地运行目标。用户多次实测表明，当前请求方式下相当于消耗约 58,000 点专属积分，留下约 2,000 点余量；这是特定条件的经验值，不是平台通用计费公式。
- 并发请求可能在达到 token 目标后仍返回用量，目标不能被宣传为精确硬上限。
- 状态文件只记录 tokens、请求数等，不记录专属/通用积分扣减和返赠到账。
- 文档将 `429 quota_exceeded_error` 同时用于速率和额度超限，必须结合可靠错误详情处理；分类不明时暂停，不能只凭该类型判定永久耗尽。

这些内容来自只读代码和状态检查；本轮未启动脚本，也未复测限流、锁或断点恢复行为。

## 4. 首版面板建议

### 配置和首次使用

1. 打开应用，看到默认服务地址及当前官方规则说明。
2. 输入 API key，选择本次会话使用或加密保存。
3. 点击“读取模型”，使用官方 `GET /v1/models` 获取列表和上下文信息；请求失败时给出明确原因。
4. 返赠模式默认选择 `sensenova-6.8-flash-lite`；其他模型显示用途与资格说明。
5. 通过“预计专属积分消耗比例”滑条和预设按钮选择本轮目标，默认 95% 档、1.2 亿 tokens，说明其基于用户实测及约 2,000 点专属积分预留量；由用户点击开始。安装、保存配置和读取模型均不会自动启动消耗。

Base URL 首版建议默认固定。是否开放高级修改待确认；若开放，要校验 HTTPS 地址并明确显示 key 即将发送到的域名，避免误填服务地址。

### 运行区

- 将比例选择放在主面板。支持 0%～95%，常用预设为 25%、50%、75%、95%；首版默认不提供 100% 档。用户运行前可自行选择，运行中的目标调整仅作用于下一轮。
- 两个已确认映射为 50% → 60,000,000 tokens、95% → 120,000,000 tokens。补充建议映射为 25% → 30,000,000、75% → 90,000,000；自定义比例采用校准表的分段插值，避免将两个人工校准档位误当作同一个精确线性积分公式。映射表可在校准后版本化更新。
- 0% 表示不执行请求，不能传给旧引擎作为无限目标。非零目标必须为正且通过上限校验；95% 档为当前已校准的最高常用档。
- 配置区展示预计消耗比例及预留量，具体 token 目标放在详情中；没有官方记录时不能显示“实际已消耗积分”。切换档位后立即更新本轮运行摘要。
- 开始、暂停、继续、停止；明确展示停止过程中仍在完成的请求。
- 当前状态、已运行时间、成功/失败请求数、输入/输出/总 tokens、速率、下一次可尝试时间。进度依据实际 tokens / 本轮选定目标计算，停止后保留真实最终用量。
- 并发、单次输入长度、最大输出、单轮 token 目标和时间上限放入高级设置。先以现有已使用的参数作为校准基线：并发 3、输入字符目标 340000、最大输出 1024、token 目标 120000000；新引擎的实际行为仍需验证。
- 临近 token 目标时减少新请求和并发，为在途请求预留预算；面板显示最终实际 usage 与目标值。此控制不能被表述为精确积分硬上限。
- 发生认证失败、模型不可用、参数错误或连续异常时给出可操作提示。积分扣减来源没有查询依据时明确显示未核实，不阻止使用已确认的经验限额策略。
- 关闭窗口进入托盘；托盘提供停止与退出；退出后没有遗留任务。该行为待实现验证。

### 调度和记录

- 主面板提供“计划运行”开关与“运行间隔（小时）”输入，可设置每隔 N 小时运行一次，默认值为 5。启用状态、间隔、下次运行时间和比例配置持久化；间隔必须为有效正数。
- 计划运行首版建议默认关闭，输入 key 或保存配置不会自动开始；用户主动开启并点击启动后按当前比例运行首轮，随后按计划创建新轮。
- 拟按每轮计划开始时间计算间隔，而不是运行完成后再等待 N 小时。上一轮未完成时跳过重叠触发，不排队补跑；临时休眠或应用未运行期间错过的周期也不连续补跑，恢复后重新明确展示下次触发时间。
- 提供“停止本轮”和“关闭计划”两个清晰操作；关闭计划取消未来触发，正在运行的任务仍可单独停止。比例与周期变更默认作用于下一轮，当前轮目标保持稳定。
- 默认 5 小时沿用已有运行策略；时间到达只表示再次运行的计划条件，不能展示“已恢复完整额度”。已知额度不足、周额度限制或用户暂停时，不继续发起消耗。
- 单实例和每账户的运行互斥，防止重复点击或重开窗口产生重复任务。
- 默认单个 key；多 key 并发属于后续范围，不能假设多个 key 会获得独立账户积分池。
- 日志脱敏、控制体积，导出前移除凭据和账户隐私；默认只记录必要用量与错误，不保存完整模型回答。
- 能证明官方到账时才展示“实际返赠”；其余显示“未查询”“待官方结算”或有依据的明确估算。

## 5. 默认限额策略与积分查询增强

本轮公开文档未找到可供 API key 调用的专属积分余额、扣减来源和返赠明细接口。这是本轮查阅范围内的结果，不等于断言平台一定没有这些接口。

此外，公开文档的模型列表包含 `pricing`，但示例价格为零，未确认专属积分的 token 换算、缓存扣减、输出权重和取整方式。不能据此构造“准确积分”公式。

首版默认采用用户已有的校准经验，余额 API 不作为基础面板开发的前置条件：

1. 默认 95% 档目标 120000000 tokens、50% 档目标 60000000 tokens，由用户自行选择。保持现有 Flash-Lite 模型和请求规模作为基线；达到选定目标后停止新增请求，并汇总在途请求的实际用量。
2. 显示“按现有实测预计消耗约 58,000 点专属积分，留约 2,000 点”，同时标注为经验估计。未经官方记录核对，不显示“本轮实际返赠 58,000 点”。
3. 经验适用前提是本轮开始时专属积分约 60,000 点，且没有其他客户端同时消耗该池。若用户实际剩余更少，应降低目标或等待恢复；默认限额不能覆盖任意起始余额。
4. 更换模型、显著调整输入/输出比例、提高目标或出现规则变化时，提示重新校准；同一个 token 总量不能假定积分扣减始终一致。
5. 积分查询、扣减来源、返赠明细和官方仅用专属积分开关作为增强能力继续确认。确认后再验证更新延迟和外部并行消耗，不能把轮询宣传为绝对保证。
6. 后续真实验证仍需用户明确授权使用凭据和发起请求。先用最小请求核查协议；完整 1.2 亿目标和官方积分对应关系的验证需单独确认消耗范围，不能称为“最小用量验证”。

定时运行首版建议默认关闭，用户主动开启后采用可配置间隔，默认 5 小时。每轮使用该轮启动时确认的比例和 token 目标。没有官方余额查询时，界面提供官方账户页面入口和明确的剩余额度核查提示。

本轮不探测控制台未公开接口，不读取或使用个人 key、登录 cookie，不调用消耗额度的接口。

## 6. 候选架构和安装包

候选选型：Electron + React + TypeScript，运行引擎放在主进程管理的独立 worker。采用同一套语言实现面板与调度，运行环境随安装包交付。此处仅提出候选方案，未锁定框架版本或执行依赖安装。

职责划分：

| 模块 | 职责 |
| --- | --- |
| UI | 配置、模型资格、运行状态、用量与错误展示 |
| 桌面宿主 | 窗口、托盘、单实例、退出流程、IPC 权限 |
| 凭据存储 | Windows 系统保护机制加密，普通配置与 key 分开 |
| API 适配器 | 官方请求结构、模型读取、usage 解析、错误归类、超时与取消 |
| 运行引擎 | 调度、请求预算、互斥、退避、暂停与停止 |
| 本地记录 | 原子写入状态、日志轮转、可恢复历史、脱敏导出 |
| 积分适配器 | 仅接入已确认的官方接口；缺失能力明确呈现 |

UI 不直接持有长期保存的 key，不向任意远程地址开放本地控制接口。配置和日志保存在用户数据目录，安装目录升级不会覆盖用户数据。

计划交付 Windows 安装程序；可选便携版、ARM64、开机启动、自动更新和代码签名另行确认。没有代码签名时，Windows 下载或安装提示必须在真实环境验收，不能仅以构建成功宣称“安装即用”。

后续 GitHub Release 交付物建议包含：安装包、SHA-256、中文首次使用说明、版本变更与已知限制。开源许可证、签名条件和正式发布均待确认。

## 7. 验收与证据

- Mock API 验证认证错误、429 分类与退避、暂时故障、取消、缺失 usage、目标超调和状态恢复。
- 验证比例控制的 50% / 95% 精确映射、0% 不发送请求、插值单调性、最大档位、重启后配置一致性和变更只作用于下一轮。
- 验证默认 5 小时间隔、自定义间隔、无效输入、无重叠运行、关闭计划、下次触发时间、休眠恢复与错过周期不连续补跑；使用模拟时钟验证长间隔，不要求测试等待完整 5 小时。
- 使用实际桌面应用验证开始/暂停/停止、重复打开、托盘、退出、重启恢复及脱敏日志。
- 在缺少开发环境的 Windows 测试账户或虚拟机完成安装、打开、配置、运行、退出和卸载验收。
- 专属积分耗用与返赠到账，需要真实官方记录和明确授权下的最小用量测试；mock 和 tokens 计数不能替代。
- 打包前检查仓库及安装产物中不存在真实 key、个人路径、账户数据和私有 Agent 资料。

阶段通过与整个产品完成分别汇报。未经真实安装验收，不标为“安装即用”；未经到账证据核对，不标为“转换验证通过”。

## 8. 待确认项

1. 已采用：主面板比例控制；95% 档为 1.2 亿 tokens、50% 档为 6000 万 tokens，默认 95%。当前实测的最高档预留约 2,000 点专属积分；新引擎需验证在途请求控制。
2. 已采用：可配置运行间隔，默认 5 小时。待确认：支持的 Windows 版本/架构、候选技术栈、托盘行为和默认启用状态。
3. 待增强：官方积分查询、精确计费、到账明细及专属积分限定能力。
4. 待确认：开源许可证、代码签名、Release 验收与后续发布授权。

本轮没有新增依赖、执行应用代码或产生真实 API 消耗。
